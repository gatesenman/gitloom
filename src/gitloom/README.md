# GitLoom 织线 0.5.1

<img src="build/icons/256x256.png" width="96" align="right" />

**GitLoom 织线** 是一款简体中文界面的 Git 桌面客户端（Windows / macOS / Linux），专为“一个项目文件夹里有几十个 Git 仓库”的场景设计：
打开 IDE 的项目目录，它会自动找出里面所有仓库（嵌套仓库、子模块、工作树），在左侧按文件夹结构列出，并用徽标标出谁有改动、谁该推送、谁该拉取。
日常的看改动、挑着暂存、写提交、推送拉取都能在一个窗口里完成；不常用的高级功能放在「更多 ▾」里，需要时再找。
内置 AI 助手，可接入国际、国内主流大模型和聚合 / 本地服务（共 23 个预设）。

- 不联网也能用；AI 是可选的，Key 只保存在本机并用系统密钥库加密（Windows DPAPI / macOS 钥匙串）。
- GitLoom 执行的每一条 git 命令都记录在「Git 命令日志」里，随时可以查看。

**0.5.1 新功能：代码地图对比（类似 codemap）**。「变更可视化」新增两个视图：**代码地图**——像 `codemap --diff` 那样把整个项目按目录列成树或方块图，
每个文件标出改动前 → 改动后的大小、行数、被多少文件引用、影响面（谁可能被改坏），自动标出「热点文件」和「可能受影响」的文件，可导出 Markdown 评审包；
**改动导览**——像 Windsurf Codemaps 那样给出带编号（1、1a、1b…）的阅读路线，按调用顺序分组，每一步直达代码，可勾「已看过」；配置 AI 后可以直接问
「优惠券是怎么生效的？」，生成只引用真实代码位置的路径图。对比范围也更顺手：标签可选、两侧一键交换、「快捷对比」（发版以来、两个标签之间、当前分支 ↔ main、未推送的提交）。详见「代码地图对比（0.5.1）」一节。

![代码地图：树状清单](screenshots/v9/71-map-tree.png)

**0.5.0 新功能：变更可视化**。一次改了几十个文件，不用再一行行读 diff：GitLoom 把「改动前 / 改动后」画成架构图、模块依赖、调用图、流程图、
时序图、状态图、类 / 数据模型和影响范围 8 种图，新增标绿、删除标红（虚线）、修改标黄，左右并排同步缩放，也可以叠加或用滑块对比。
不需要 AI 也能用（tree-sitter 静态分析 9 种语言）；配置了 AI 后还能一键生成「按职责分层的架构图、业务流程、关键调用时序」。详见下方「变更可视化」一节。

![变更可视化：架构图前后对比](screenshots/v8/10-arch-side.png)

**0.4.3 修复**：「历史」提交详情里连续点击「AI 解释」会让界面不停闪烁。现在该按钮是开关：生成中显示转圈和「停止」，重复点击不会再发请求；
切换提交、关闭或离开页面会取消请求；结果按“提交 SHA + 服务商/模型”缓存，再次打开立即显示，可「重新生成」；结果显示在固定高度的面板里，
流式文字按帧合并刷新，差异区不再跳动；出错时在面板内用中文提示并可「重试」。变更页「AI 解释」、提交框「AI 生成 / AI 审查」、AI 助手对话、
「测试连接 / 获取模型」同样改为单次请求 + 可停止；抓取 / 拉取 / 推送、全部拉取、提交也不会被连点重复触发。

## 界面布局

```
┌ 侧边栏 ───────────┐┌ 顶栏：项目 › 仓库 › 分支      [抓取 拉取↓ 推送↑]  搜索命令 Ctrl+K   ⋯ ┐
│ 项目切换 / 筛选    ││ 概览 · 跨仓库变更 │ 变更 · 历史 · 分支 · 更多 ▾                       │
│ 树 / 列表 / 状态   │├──────────────────────────────────────────────────────────────────┤
│ 最近 · 置顶        ││                                                                  │
│ 项目结构（仓库树） ││                      当前标签的内容                               │
│ 24 个仓库 · 4 有改动 ⓘ││                                                               │
└───────────────────┘└──────────────────────────────────────────────────────────────────┘
```

| 位置 | 标签 | 做什么 |
|---|---|---|
| 项目级 | **概览** | 项目里所有仓库一张表：分支、状态、最近提交；批量抓取 / 拉取 / 推送 / 切换分支 / 储藏 / 运行命令 |
| 项目级 | **跨仓库变更** | 把所有仓库的未提交改动放在一起看、一起提交（只有多仓库项目才显示） |
| 仓库级 | **变更** | 看差异、按文件 / 块 / 行暂存、写提交信息、提交并推送、解决冲突 |
| 仓库级 | **历史** | 提交列表或彩色分支图，查看每次提交改了什么，cherry-pick / revert / reset |
| 仓库级 | **分支** | 分支与标签 · 储藏 · 工作树 三个子页 |
| 仓库级 | **更多 ▾** | 整理提交（变基）· 二分查错 · 文件追溯 · 子模块（仓库有子模块时才出现）· PR 与 Issue · AI 助手 |
| 右上角 ⋯ | **设置** | 通用设置、AI 模型、PR 平台 Token、**Git 钩子**（当前仓库） |

所有功能都能在命令面板（Ctrl/⌘+K）里搜到。

## 每个功能的使用场景

### 侧边栏：项目与仓库树
> “公司的 EVER-BUDDY 目录里有 20 多个服务仓库，还有 AI 工具建的 `.kilo/worktrees`。打开 GitLoom 后，我一眼就能看到哪几个有改动、哪几个要推送。”

- 自动扫描项目目录，跳过 `node_modules` 等目录；文件夹会汇总其下所有仓库的徽标。
- **只看有改动**（筛选栏右侧的 ✎ 按钮）：只留下有未提交改动、冲突或待推送 / 待拉取的仓库。这个开关会被记住，底部会显示「只看有改动 ×」，点一下即可恢复显示全部。
- **徽标说明**：点底部的 ⓘ 可查看图例。黄色数字表示改动文件数，↑ 表示待推送，↓ 表示待拉取；另有冲突、分离 HEAD、**无上游**（分支还没推送过）几种。
- 鼠标悬停在仓库上会显示完整路径、类型、分支 → 上游，以及领先 / 落后 / 改动数。
- 支持置顶、最近、树 / 列表 / 按状态分组三种显示方式，紧凑 / 舒适两种密度。右键可隐藏仓库（能撤销）。

### 概览：一键同步
> “早上来了想把所有落后的仓库都拉到最新，下班前把领先的都推上去，不想一个个点。”

- **全部拉取 N 个落后**：对所有落后于上游的仓库执行 `git pull --ff-only`，不会产生合并提交。
- **推送所有领先的 N**：推送所有有待推送提交的仓库。
- 底部结果面板会显示进度和每个仓库的结果，可勾选「仅显示失败」。
  - 成功时用中文写明结果，例如“已快进 3 个提交 · 2 个文件（+10 −1）”。
  - 失败时说明原因和建议，例如“本地和远程分叉了，可以变基拉取或拉取合并”“连接不到远程仓库，请检查网络 / 代理 / VPN”。失败行旁有「去处理」按钮，可直接打开该仓库。
- 没有上游的分支会单独提示数量，避免被悄悄跳过。

![一键拉取结果](screenshots/v6/02-overview-pull-all-results.png)

### 变更：看改动、挑着提交
> “改了几个文件，想先看看到底动了哪些行，挑出要提交的部分，写一句说明后提交。”

- Monaco 差异编辑器，支持并排 / 统一两种布局。默认折叠没改动的代码，点折叠条可展开一段；点「**显示全部行**」可一次展开整个文件，这个选择会被记住。
- 「分块暂存」页可以按块或按行暂存。
- **键盘操作**：`J` / `K` 在文件间上下移动，`S` 暂存（光标自动跳到下一个文件，可以连按），`U` 取消暂存，`Ctrl+Enter` 提交。在输入框或差异编辑器里打字时这些键不会触发。
- **提交信息历史**：点提交框上的「历史」，从最近 20 条提交信息中选一条复用，支持搜索。
- **草稿不丢**：没写完的提交信息按仓库自动保存，切到别的仓库或重启应用后还在。
- AI 生成提交信息、AI 审查暂存区（流式输出）；「选项」里有 修改上次提交 / Sign-off / 跳过钩子。
- 冲突时显示三栏视图：可一键采用我方 / 对方、用编辑器解决、让 AI 给合并建议，然后继续或中止。

![变更视图](screenshots/v6/04-changes-keys-history.png)

### 出错时：大白话 + 一键修复
> “推送被拒了，提示一大段英文，我只想知道该点哪里。”

常见 git 错误会翻译成一句中文原因加一条建议，提示框里直接带修复按钮：

| 情况 | 提示 | 按钮 |
|---|---|---|
| 分支没有上游 | 当前分支还没有上游分支 | 推送并设置上游 |
| 推送被拒（远程有新提交） | 推送被拒绝：远程有你没有的新提交 | 变基拉取 |
| 本地和远程分叉 | 本地和远程分叉了 | 变基拉取 |
| 本地改动挡住了拉取 / 切换 | 本地有未提交的改动挡住了 | 储藏后重试 |
| 合并冲突 | 有合并冲突需要处理 | 去处理 |
| 分离 HEAD | 处于“分离 HEAD”状态 | 在此建分支 |
| 网络 / 代理问题 | 连接不到远程仓库 | 重试 |
| 凭据错误 / 仓库不存在 | 身份验证失败 / 远程仓库不存在或无权访问 | 检查远程 |
| `index.lock` 被占用 | Git 正被其他程序占用 | 重试 |

![友好的错误提示](screenshots/v6/06-friendly-error-toast.png)

### 历史
> “想知道上周谁改了登录逻辑，顺便把那个修复 cherry-pick 到发布分支。”

- 可在提交列表和彩色分支图（类似 GitKraken / Fork）之间切换，支持搜索。可以查看提交详情和每个文件的差异，并让 AI 解释这次提交。
- 支持 cherry-pick、revert、reset、从提交建分支 / 打标签；引用日志（reflog）可以找回“丢失”的提交。

### 分支（分支与标签 · 储藏 · 工作树）
> “做到一半要去修线上 bug：先储藏，或者干脆开一个工作树并行改。”

- 分支 / 标签 / 远程的增删改、合并、变基、比较。
- 储藏：push / apply / pop / drop / 转为分支 / 预览。
- 工作树：列表、创建、打开、锁定、移除、prune。

### 更多 ▾
- **变更可视化**（0.5.0 新增，0.5.1 增加代码地图 / 改动导览）：“同事提了一个动了 30 个文件的重构 PR，想先看一眼「分层有没有变、哪些模块之间多了依赖、状态机多了哪个状态」，再决定从哪里开始读代码。”详见下一节。
- **整理提交（变基）**：“推送前想把 5 个零碎提交合并成 1 个，再改一下说明。”支持拖拽排序和 pick / reword / squash / fixup / drop。
- **二分查错**：“上周还好好的，今天坏了，中间有 200 个提交，用对半查找定位是哪次搞坏的。”
- **文件追溯**：“这一行是谁、在哪次提交里写的？”包含逐行追溯 / 文件历史、Pickaxe 代码搜索、比较分支、安全清理、配置编辑、签名引导、LFS。
- **子模块**：init / update / sync / deinit（只有仓库有子模块时才出现）。
- **PR 与 Issue**：GitHub / GitLab 的 PR·MR 列表与创建、Issues、CI 状态。Token 可在页面内直接填写。
- **AI 助手**：多轮对话，自动附带当前仓库和差异作为上下文，回复流式输出；也可以把自然语言转成 git 命令，确认后执行。

### 设置 → Git 钩子
> “希望每次提交后自动更新一份给大模型看的项目百科。”

可启用 / 禁用 / 编辑钩子，并提供模板库。其中 **llmwiki** post-commit 模板会自动维护 `docs/llmwiki/`，详见文末。

## 变更可视化（0.5.0）

把一次改动画成「改动前 / 改动后」两张对齐的图，先看结构，再看代码。

**入口**
- 「更多 ▾ → 变更可视化」：第一次打开有说明卡片；工作区有改动时默认分析工作区，否则分析最新提交。
- 「历史」提交详情 → **可视化对比**（该提交 vs 父提交）。
- 「文件追溯 → 比较分支」→ **可视化对比**（两个分支 / 标签，按合并基准比较，相当于 PR 视角）。
- 「变更」差异工具栏 → **可视化**（工作区全部改动 vs HEAD）；「跨仓库变更」每个仓库标题上也有同样的按钮。

**范围**：工作区 · 单个提交 · 提交范围（A..B）· 分支对比（base...head）；可以填路径 / 模块过滤（例如 `src/services`）。

**8 种图**
| 图 | 回答的问题 | 来源 |
| --- | --- | --- |
| 架构图 | 分层（表现层 / 接口层 / 业务层 / 数据层 / 基础层）有没有变？多了哪个组件、哪条跨层依赖？ | 目录与文件名推断；可切换为「AI 分层」 |
| 模块依赖 | 哪些文件 / 包之间新增或去掉了 import？ | 静态分析 |
| 调用图 | 改动的函数被谁调用、又调用了谁？ | 静态分析 |
| 流程图 | 某个函数的 if / 循环 / try 分支前后怎么变了？配置 AI 后还有「业务流程」 | 静态分析（控制流）· AI |
| 时序图 | 一次请求经过哪些模块、顺序怎么变？（含 alt / loop / opt / par 框） | 静态调用链 · AI |
| 状态图 | 状态机多了 / 少了哪些状态和转换？（联合类型、枚举、switch 转换） | 静态分析 · AI |
| 类 / 数据模型 | 类、接口、枚举的字段与方法增删，继承 / 实现 / 组合关系 | 静态分析 |
| 影响范围 | 改动会波及哪些上游调用方（按距离 1 跳 / 2 跳 / 3 跳以上着色） | 静态分析 |

**看图**
- 三种对比方式：**并排**（两边同步平移缩放）、**叠加**（一张图上用颜色区分）、**滑块**（拖动分界线擦除对比，或一键切换 改动前 / 对半 / 改动后）。
- 图例：新增（绿）、删除（红色虚线）、修改（黄）、移动（蓝）、未变（灰）；顶部摘要条显示文件 / 模块 / 依赖 / 函数 / 调用 / 类型 / 状态 / 路由的增删改数量。
- **只看变更 + N 跳**：只保留改动的节点和它周围 0–3 层邻居；大图（模块 > 40、调用 > 90 个）默认开启。超过 150 个节点自动把未改动的目录折叠成簇，双击展开。
- 搜索节点（自动居中高亮）、小地图、适应窗口、放大缩小；悬停连线显示 import / 调用所在的代码行。
- 点节点打开侧栏：改动状态、前后位置、成员变化、相关连线、代码片段 diff；**打开差异** 用 Monaco 并排查看整个文件，**聚焦邻居**、**复制位置**。
- 导出：PNG 图片、SVG 矢量图，或复制为 Mermaid / PlantUML 文本（可直接贴进 PR 描述或文档）。
- 深色 / 浅色主题，1024 px 宽度下也不会出现横向滚动；同一输入的布局完全一致（排序输入 + 固定随机种子）。

**语言**：TypeScript、TSX、JavaScript、Python、Java、Go、Rust、C#、Kotlin（tree-sitter 语法分析）；C / C++ / Ruby / PHP / Swift / Scala / Vue / Svelte / Dart / Lua 只分析文件级依赖。

**AI 增强（可选）**：点「AI 增强」后，把静态分析结果和精简过的 diff 发给「设置 → AI 模型」里的模型，让它返回严格的 JSON（zod 校验；
不合格会把错误发回去让它修正一次），生成按职责分层的架构图、业务流程、关键调用时序和状态机。结果按「分析范围 + 模型」缓存，随时可停止；
没有配置 AI 时，静态图照常可用，AI 相关的位置会显示「去配置 AI」。

**用户故事**
1. 评审重构 PR：在「文件追溯 → 比较分支」里选 `main` 和 `refactor/service-layer`，点「可视化对比」。架构图里一眼看到新增了「业务层 / services」，
   接口层不再直接依赖数据层；状态图里 `OrderStatus` 多了 `cancelled`、`refunded` 两个状态和 `cancel`、`refund` 两条转换。点 `OrderService` 节点 →「打开差异」，从这里开始读代码。
2. 提交前自查：在「变更」页点「可视化」，确认这次只动了预期的模块，影响范围里没有意外波及的调用方。
3. 写变更说明：在时序图里选 `payOrder()`，导出 PNG 或复制 Mermaid，贴进 PR 描述。
4. 接手陌生仓库：对最近一个大提交点「可视化对比」，配合「AI 增强」的分层架构图，快速了解模块划分。

**实现**：分析在主进程的 worker 线程池里进行（最多 4 个，web-tree-sitter + 预编译语法 WASM），按 blob 哈希缓存解析结果；渲染用 React Flow，
布局用 ELK（在 Web Worker 中计算，界面不卡）。性能（Linux，1500 个文件的仓库、一次改 60 个文件）：分析不到 1 秒，各视图首次渲染 0.7–4 秒；
GitLoom 自身仓库（80 个源文件）的一个提交约 0.5 秒（命中缓存）到 1.7 秒（冷启动）。

## 代码地图对比（0.5.1）

需求来自用户：「类似 codemap 对比的一些支持」。调研了 Windsurf / Devin Codemaps、开源 `codemap` CLI、CodeSee Review Maps、Sourcetrail，
取其中最适合「改动前 / 改动后对比」的部分（调研与取舍见 `docs/PLAN.md` §10）。两个新视图排在「变更可视化」最前面，范围选择与原来相同。

**代码地图**（回答：改动落在项目的哪里？谁依赖这些文件？会波及多大范围？）
- **树状清单**：按目录（单子目录自动合并成 `src/main/viz`）列出文件，列：状态、大小（前 → 后）、行 +/−、被引用（前 → 后，新增 / 失去的引用方 +N / −N）、影响面（直接或间接依赖它的文件数）。
- **方块图**：面积 = 文件大小，按目录嵌套；「改动前 / 改动后」切换时方块平滑变形——新增的文件长出来、删除的文件消失、变大变小一目了然。
- **着色**：按改动（新增 / 删除 / 修改 / 移动 / 可能受影响 / 未变）、按热度（被引用数）、按大小变化。
- **只看改动 / 全部文件**：默认只列改动的文件、可能受影响的文件（没改，但依赖了改动的文件）和引用方变化的文件；全部文件模式下没改动的目录默认折叠。
- **热点文件**：被 ≥ 5 个文件引用（大仓库取前 3%）的文件标 🔥；改动了热点文件时顶部出现提示条，点名字直接定位。模块依赖 / 影响范围图里的节点也会显示 🔥。
- **依赖覆盖**：像 codemap 一样说明结论有多可信——完整 / 部分（大仓库只解析了改动所在目录）/ 无（没有源代码）。
- 点文件 → 侧栏显示补丁，**打开差异** 看整个文件；文件路径筛选；悬停显示全部数字。
- **导出**：Markdown 评审包（概要、改动的热点文件、改动文件表、引用关系变化、可能受影响的文件——可直接贴进 PR 描述）、JSON（`gitloom.codemap/v1`）、PNG。

**改动导览**（回答：从哪里开始读？按什么顺序？）
- **阅读路线**（无需 AI）：改动的源文件按「调用方在前、被调用方在后」排序（循环依赖也能稳定排序），按表现层 / 接口层 / 业务层 / 数据层 / 基础层分组；
  每个文件下列出改动的函数（1、1a、1b…），写明为什么要看（新增 / 被几个文件引用 / 热点 / 引用了第几步）；文档、配置等放在最后一组。
- 右侧是同一路线的图：每个文件一个节点、里面列出改动的函数，虚线表示阅读顺序，实线表示 import / 调用；并排 / 叠加 / 滑块照常可用。
- 每一步可勾「已看过」，显示进度条；进度按「分析范围」保存在本机。点步骤 → 侧栏直接显示该函数的代码差异。导出 Markdown 阅读清单。
- **AI 路径**（可选，类似 Codemaps）：输入问题（例如「优惠券是怎么生效的？」，留空则是「这次改动的主要执行路径」），AI 只能从静态分析给出的候选位置
  （改动的文件 / 函数 + 它们直接调用或被调用的未改动函数，编号 C1、C2…）里挑步骤，写分组、导读和每步说明——不会编造文件或行号。
  结果 zod 校验（引用不存在的位置会把错误发回让它修正一次），按「范围 + 问题 + 模型」缓存，可停止。

**更顺手的对比范围**
- 提交范围 / 分支对比的输入框里可以直接选标签；⇄ 一键交换两侧。
- 「快捷对比」菜单：工作区 ↔ HEAD、最新提交、最近 5 个提交、最新标签 → HEAD（发版以来）、两个标签之间、当前分支 ↔ main（类似 PR）、还没推送的提交。

## 可视化深度优化（0.5.2）

需求原话：「可视化的深度优化一版本」。先把所有视图在 GitLoom 自己的仓库、1500 文件仓库、Python / Java 示例上，按 1024 / 1440 / 1920 宽、深浅两种主题逐一实测、截图、量化
（缩放比例、视野内改动数、穿过无关方块的连线、交叉点、被截断的标签、工具栏换行），再按问题改。审计结论与前后数据见 `docs/PLAN.md` §11。没有删除任何功能。

**一打开就看得清**
- **连线不再穿过方块**：模块依赖 / 调用图 / 类 / 影响范围 / 流程 / 状态图改用 ELK 计算的正交走线（圆角折线），文件夹之间的连线**捆成一束**再分到各个文件；
  小图自动在"层次布局"和"捆绑布局"里挑交叉更少、能放得更大的那个。GitLoom 自己这次改动的模块依赖图：穿过方块的连线 81 → 5。
- **以改动为中心折叠**：节点多时，没改动的文件夹 / 文件折叠成「其他 N 个」「目录名」这样的分组（叠纸样式），改动的节点一个不少；**单击分组展开**，底部「收起 N 组」一键折回。
- **开局就能读**：整张图缩到看不清（< 50%）时，不再硬塞进窗口，而是自动对准"改动最密集的一块"并放到可读大小（≈ 75%）；左下 ⛶ 随时看全图。
- **按窗口形状排布**：互不相连的几块按窗口长宽比排成几行，不再是一长条。
- **语义缩放**：缩得很小时只显示方块和放大的分组名，中等时隐藏次要文字，放大后显示全部细节。
- **标签更干净**：文件夹里的节点不再重复写文件夹路径；函数节点的 `orders.ts:20` 改成「第 20 行」（文件名已经写在分组上）；按实际字体估算宽度，标签不再被截断。

**看改动的工具**
- 底部条：**这张图改了什么**（"新增 9 个函数，修改 7 个，删除 1 个，多了 15 条调用"）+ **‹ 改动 i/N ›** 逐个跳到每一处改动（按阅读顺序）。
- **键盘**：`N` / `]` 下一处、`Shift+N` / `[` 上一处、`Enter` 打开详情、`F` 看全图、`C` 对准改动、`+` / `-` 缩放、方向键平移、`/` 搜索、`Esc` 清除。
- **两侧联动高亮**：鼠标停在任一侧的方块上，左右两张图里同一个方块和它的连线、邻居一起高亮。
- **两点之间的路径**：按住 Shift 点两个方块，高亮它们之间最短的调用 / 依赖路径（顶部显示"A → B · 2 步"），其余变暗。
- **叠加模式「前 / 叠加 / 后 / 播放」**：一张图里淡出新增或删除的内容，或自动来回播放，看哪些东西出现、消失。
- **小地图**只在图比窗口大时出现，且可开关；窗口很窄时默认不挡图。
- **AI 解读本图**（可选）：AI 只根据图里的节点和连线写 3～6 条要点，提到的「名字」是可点的标签，点一下跳到图上对应的方块；按结果缓存。

## AI 模型（设置 → AI 模型）

- **多个配置**：可以同时添加 DeepSeek、Claude、公司中转、本地 Ollama 等多个配置。每个配置有自己的地址、Key 和模型；Key 用 Electron safeStorage 加密后保存。
- **选服务商**：服务商按 国际 / 国内 / 聚合与本地 分组，带首字母标识，可以按名称或模型搜索（如“千问”“claude”“本地”）。选好后会自动填入官方地址；如需 Key，会给出“如何获取 Key”链接。
- **获取模型**：从服务商的 `/models` 接口拉取模型列表；拉取失败时改用内置的推荐模型列表。
- **测试连接**：发一次很短的流式请求，显示首字延迟和总耗时。出错时会给出中文原因，例如 Key 无效、地域不匹配、余额不足、模型不存在、限流、服务端错误、连不上本地服务。
- **按任务选模型**：提交信息、代码审查、解释差异、AI 对话可以分别指定配置和模型。
- **备用链**：主模型因网络、限流、余额等问题不可用时，按顺序自动改用备用配置。已经开始输出的回答不会中途切换。
- **流式输出**：OpenAI 兼容、Anthropic Messages、Azure 三种协议都支持流式输出。

## llmwiki 钩子

设置 → Git 钩子 → 模板 → 「llmwiki：自动维护 LLM 项目百科」→ 安装。之后每次提交都会生成：

- `docs/llmwiki/index.md`：README 摘要、基本信息、目录结构、文件类型统计、热点文件、最近提交
- `docs/llmwiki/changelog.md`：每次提交记一条（最新的在前）；配置了 AI 时追加「AI 摘要」

通过 GitLoom 提交时，当前默认 AI 配置会以环境变量（`LLMWIKI_BASE_URL` / `LLMWIKI_MODEL` / `LLMWIKI_API_KEY`）传给钩子。在命令行提交时，可以自己设置这些环境变量，或使用 `git config llmwiki.baseUrl/model`。`LLMWIKI_SKIP=1` 可跳过一次。

规划与调研见 [docs/PLAN.md](docs/PLAN.md)，多仓库 UX 见 [docs/MULTI-REPO.md](docs/MULTI-REPO.md)。
